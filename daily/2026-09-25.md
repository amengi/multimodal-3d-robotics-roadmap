## 概念一：类、封装与不变式

`struct Point3` 只是三个数的轻量聚合；`Camera` 则需要保证一组相互相关的参数总是可用的，所以用类：

```cpp
class Camera {
public:
    Camera(double fx_px, double fy_px, double cx_px, double cy_px,
           std::array<double, 9> rotation_cw,
           std::array<double, 3> translation_cw_m);
    Pixel project(const Point3& world) const;
private:
    double fx_px_, fy_px_, cx_px_, cy_px_;
    std::array<double, 9> rotation_cw_;
    std::array<double, 3> translation_cw_m_;
};
```

不变式是“每个已构造对象在公共方法调用前后都必须成立的条件”。今天至少有：

1. `fx,fy>0` 且所有参数有限；
2. `R_cw` 行两两正交、单位长度、行列式 `+1`；
3. 投影时 `Z_c>0`，否则点不在针孔相机前方。

构造函数使用成员初始化列表建立完整状态，然后统一验证。私有成员防止调用者绕过检查把 `fx` 改成 0。封装不是“隐藏代码”，而是把可以信赖的状态边界放在一处。

## 概念二：RAII、析构与所有权

RAII 把成对操作绑到对象寿命：

```text
进入作用域 -> 构造 ProjectionReport -> 打开文件
               -> append(...)          -> 文件有效
离开作用域 -> ~ProjectionReport     -> 写收尾；ofstream 自动关闭
```

无论正常到达大括号、`return` 还是中间抛出异常，已完成构造的局部对象都会按逆序析构。这比在每条控制流路径上手写 `close()` 可靠。析构函数不应抛出异常；本例只写一行收尾标记和更新计数。

### 三种关系不要混淆

| 表达 | 含义 | 能否复制 | 今日例子 |
|---|---|---|---|
| `Camera camera{...}` | 值语义，局部对象自身管寿命 | 视类定义 | 更简单的默认选择 |
| `const Camera& camera` | 非拥有、不延长生命的只读别名 | 引用可传递，对象不被复制 | `run_dataset` 借用相机 |
| `std::unique_ptr<Camera>` | 独占动态对象所有权 | 不可复制，可 `std::move` | 演示所有权与自动删除 |

`unique_ptr` 离开作用域时销毁对象，不需要手写 `delete`。但“智能指针”不是高级代码标志：如果对象只需要当前作用域寿命，直接局部值通常更清楚。

## 概念三：内外参和针孔投影

采用列向量语义，世界点先变到相机系：

```text
P_c = R_cw P_w + t_cw
```

- `P_w:(3,)`、`P_c:(3,)`、`t_cw:(3,)`，单位 m。
- `R_cw:(3,3)` 无量纲，将 world 坐标分量表示到 camera 坐标系。
- 下标 `cw` 表示 world-to-camera；不能只写含糊的 `R,t`后猜方向。

再做无畸变针孔投影：

```text
u = f_x X_c/Z_c + c_x
v = f_y Y_c/Z_c + c_y
```

`f_x,f_y,c_x,c_y,u,v` 都以 pixel 表示。今天 `K=(100,100,320,240) px`、`R=I`、`t=0`：

```text
P_w=(-1,-1,2)m -> P_c=(-1,-1,2)m
u=100*(-1/2)+320=270 px
v=100*(-1/2)+240=190 px
```

这是可检测的普通几何基线。真实相机还需要考虑畸变、标定误差、像素中心约定和可见范围；本例不包含这些。

## 概念四：联合熵、条件熵与链式法则

定义两个离散随机变量：

- `X=0` 若 `Z_c<3m`（near），否则 `X=1`（far）。
- `Y=0` 若 `u<c_x`（left），否则 `Y=1`（right）。

8 个等权教学点给出：

| | `Y=left` | `Y=right` | `P(X)` |
|---|---:|---:|---:|
| `X=near` | `3/8` | `1/8` | `4/8` |
| `X=far` | `1/8` | `3/8` | `4/8` |
| `P(Y)` | `4/8` | `4/8` | `1` |

联合熵使用联合概率：

```text
H(X,Y) = -Σ_x Σ_y p(x,y) log₂ p(x,y)
       = -2[(3/8)log₂(3/8)] - 2[(1/8)log₂(1/8)]
       = 1.811278 bit
```

边缘分布均为 `(1/2,1/2)`，所以 `H(X)=H(Y)=1 bit`。条件熵：

```text
H(Y|X) = Σ_x p(x) H(Y|X=x)
       = (1/2)H₂(1/4) + (1/2)H₂(3/4)
       = 0.811278 bit
```

链式法则：

```text
H(X,Y) = H(X) + H(Y|X)
1.811278 = 1.000000 + 0.811278 bit
```

直觉：要编码一对 `(X,Y)`，可以先编 `X`，再在已知 `X` 的条件下编 `Y`。当 `X` 和 `Y` 有关联时，已知 `X` 会减少 `Y` 的剩余不确定性。这不证明深度导致左右位置；点集是人为构造的。

## 误区与失败边界

| 现象/说法 | 原因 | 修正 |
|---|---|---|
| 成员有随机值 | 构造函数体内遗漏赋值或默认初始化 | 使用成员初始化列表，构造后检查不变式 |
| 手写 `new/delete` 或 `open/close` 分散各处 | 资源释放依赖每条控制流路径 | 用 `unique_ptr`、`ofstream` 或自定义 RAII handle |
| 所有对象都用 `unique_ptr` | 把工具当目标 | 优先局部值；只在需要动态寿命/转移时用智能指针 |
| 投影为 `nan/inf` | `Z_c=0`或非有限输入 | 进入公式前检查有限且 `Z_c>0` |
| 点向反方向移动 | 混淆 `T_cw` 和 `T_wc` | 写出 `P_c=R_cwP_w+t_cw`，用已知点手算 |
| `H(Y|X)` 大于 `H(Y)` | 联合表、边缘化或对数底错 | 先检查和为 1，再用链式交叉验证 |
| 把 `0.811278 bit` 当像素误差 | 混淆分布不确定性和几何误差 | 投影用 px 误差验收；熵用 bit 报告 |
| 说“深度决定左右” | 把统计关联误当因果 | 只说此固定样本中条件不确定性下降 |
