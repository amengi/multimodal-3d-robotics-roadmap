## 概念一：CMake 管理的是 target 图

### 1. configure、generate、build

命令：

```bash
"$DAY019_CMAKE" -S materials/day019 -B /tmp/day019-build \
  -DCMAKE_BUILD_TYPE=Release
"$DAY019_CMAKE" --build /tmp/day019-build --parallel 2
```

- **configure**：读取 `CMakeLists.txt`，探测编译器/平台，计算变量和 target 属性，写 `CMakeCache.txt`。
- **generate**：为选定 generator 产生原生构建系统，例如 Ninja 或 Unix Makefiles。
- **build**：调用生成器执行编译、归档和链接；`cmake --build` 屏蔽具体生成器命令差异。
- **source tree**：`materials/day019/`，只放手写源文件。
- **build tree**：`/tmp/day019-build/`，放 cache、对象、库、可执行和测试元数据。

“CMake 编译 C++”是简写；真正编译的是被选中的编译器，CMake 负责生成并驱动构建规则。

参考：[CMake Getting Started](https://cmake.org/cmake/help/latest/guide/tutorial/Getting%20Started%20with%20CMake.html)只看 `cmake -B build` 与 `cmake --build build`，6 分钟；看完能删除整个临时 build tree 后重新生成，而不编辑生成文件。

### 2. target 与文件的区别

本课 `CMakeLists.txt` 的核心关系：

```cmake
add_library(divergence STATIC src/divergence.cpp)
target_include_directories(divergence PUBLIC include)
target_compile_features(divergence PUBLIC cxx_std_17)

add_executable(divergence_demo app/main.cpp)
target_link_libraries(divergence_demo PRIVATE divergence)
```

`divergence` 是逻辑 target；它最终通常生成 `libdivergence.a`，但 target 还携带源文件、include 路径、语言特性和对消费者的 usage requirements。应用链接 target 名称，CMake 再决定对象/库路径和构建顺序，避免手写脆弱的绝对路径。

参考：[CMake Buildsystem](https://cmake.org/cmake/help/latest/manual/cmake-buildsystem.7.html)只看 Binary Targets，8 分钟；看完能区分逻辑依赖 `divergence` 与生成文件 `libdivergence.a`。

### 3. PUBLIC、PRIVATE、INTERFACE

把“谁自己需要”和“谁的消费者需要”分开：

| 作用域 | target 自己使用 | 链接它的消费者使用 | 今天的例子 |
|---|---|---|---|
| `PRIVATE` | 是 | 否 | demo 内部链接 `divergence` |
| `PUBLIC` | 是 | 是 | 库自己和消费者都需要公共 include 路径与 C++17 |
| `INTERFACE` | 否 | 是 | 纯头文件库常见，本课不创建 |

`app/main.cpp` 包含 `day019/divergence.hpp`，因此 include 路径必须通过库的 `PUBLIC` interface 传播给 demo。若改为 `PRIVATE`，库自身能编译，但消费者找不到公共头文件。

参考：[`target_include_directories`](https://cmake.org/cmake/help/latest/command/target_include_directories.html)只看命令签名和属性传播，8 分钟；看完能为公共头/私有实现选择作用域。

### 4. CTest 是构建图的一部分

```cmake
include(CTest)
if(BUILD_TESTING)
  add_executable(divergence_tests tests/test_divergence.cpp)
  target_link_libraries(divergence_tests PRIVATE divergence)
  add_test(NAME divergence_unit COMMAND divergence_tests)

```

`include(CTest)` 默认提供 `BUILD_TESTING` 选项并启用测试。`add_test` 注册“运行哪个命令算一项测试”，不会自动替你写断言。今天断言在 `test_divergence.cpp` 中，CTest 负责调度和汇总退出码。

参考：[CTest module](https://cmake.org/cmake/help/latest/module/CTest.html)只看 `BUILD_TESTING` 与示例，5 分钟；看完能解释“测试程序构建成功”不等于“测试已运行”。

## 概念二：KL、交叉熵、JS 与概率基线

### 1. 随机变量、shape、支持集与单位

令离散随机变量 `X∈{0,1}`。两种条件/数据源给出：

```text
p=(p0,p1)=(0.5,0.5)
q=(q0,q1)=(0.75,0.25)
shape: (K,)=(2,)
```

这里类别 0/1 只是同一事件空间的两个结果，不是两个模态，也没有坐标单位。概率无量纲。所有对数使用 `log2`，所以信息量单位是 bit；换成自然对数会得到 nat，数值乘以 `ln 2` 的关系变化，不能混用。

**支持集**是概率大于 0 的结果集合。`KL(p||q)` 有限要求 `p_i>0` 的位置也有 `q_i>0`；也称 `p` 对 `q` 绝对连续（离散情形）。

### 2. 熵与交叉熵手算

```text
H2(p) = -sum_i p_i log2 p_i
      = -0.5*(-1)-0.5*(-1)
      = 1 bit

H2(p,q) = -sum_i p_i log2 q_i
         = -0.5 log2(0.75)-0.5 log2(0.25)
         = 0.20751875 + 1
         = 1.20751875 bit
```

直觉：若数据按 `p` 出现，却使用为 `q` 设计的理想码，平均编码代价是交叉熵。这里是数学期望，不代表本课真的实现了压缩器。

### 3. KL 的定义、方向与恒等式

```text
D_KL(p||q) = sum_i p_i log2(p_i/q_i)
            = H2(p,q)-H2(p)
            = 0.20751875 bit

D_KL(q||p) = 0.75 log2(0.75/0.5)+0.25 log2(0.25/0.5)
            = 0.18872188 bit
```

所以 KL：

- 非负，且离散分布相同时为 0；
- 一般不对称；
- 不满足普通距离所需的对称性，不能叫严格 metric；
- 若 `p_i>0,q_i=0`，该项为无穷；
- 方向必须由问题决定，不能只挑数值较好看的方向。

参考：[Deep Learning Book Ch.3](https://www.deeplearningbook.org/contents/prob.html)只看 KL 非负/不对称、Figure 3.6 和式 3.51，12 分钟；看完能说明交叉熵最小化与固定 `p` 下 KL 最小化的关系。

### 4. JS：先构造混合分布

等权 Jensen–Shannon 散度：

```text
m = 0.5(p+q) = (0.625,0.375)
JS(p,q) = 0.5 KL(p||m)+0.5 KL(q||m)
        = 0.04879494 bit
```

因为混合分布在 `p` 或 `q` 有质量的位置也有质量，有限离散分布的 JS 不会因单边零概率而发散。等权、`log2` 时 `0<=JS<=1 bit`，并且 `JS(p,q)=JS(q,p)`。若权重或对数底改变，上界数值也改变，不能脱离定义背诵“JS 最大为 1”。

JS 的平方根在合适条件下是 metric；JS 本身不要自动叫“距离”。本课只报告散度。

### 5. 普通概率基线：TV

总变差：

```text
TV(p,q)=0.5*sum_i |p_i-q_i|
       =0.5*(0.25+0.25)=0.25
```

TV 对称、范围 `[0,1]`、不依赖对数方向，是本课的普通概率基线。它与 KL/JS 权重不同，数值不能直接按大小排序谁“更好”。报告 TV 可防止把所有差异都压缩成一个方向敏感的 KL。

参考：[MIT 6.441 Chapter 1](https://ocw.mit.edu/courses/6-441-information-theory-spring-2016/resources/mit6_441s16_chapter_1/)只看 divergence 定义、main inequality 相关陈述，10 分钟；看完能写出使用某个散度前必须固定的分布和支持条件。

## 跨线失败实验：支持错配与平滑

令：

```text
p=(1,0), q=(0,1)
```

`p` 认为结果 0 必然发生，而 `q` 给结果 0 零概率，因此 `KL(p||q)=infinity`。等权 JS 用 `m=(0.5,0.5)`，得到 `JS=1 bit`；TV 为 1。这是最大分离的二元例子。

为避免零概率，代码定义加性平滑：

```text
p_epsilon=(1+epsilon, epsilon)/(1+2epsilon)
q_epsilon=(epsilon, 1+epsilon)/(1+2epsilon)
```

运行：

```bash
/tmp/day019-build/divergence_demo --csv /tmp/day019-build/smoothing.csv
sed -n '1,8p' /tmp/day019-build/smoothing.csv
```

预期：

| epsilon | KL(p||q), bit | JS, bit |
|---:|---:|---:|
| 0 | `inf` | 1.000000 |
| `1e-6` | 19.931530 | 0.999979 |
| `1e-3` | 9.947332 | 0.988612 |
| `1e-2` | 6.527658 | 0.920510 |
| `5e-2` | 3.993016 | 0.733235 |

失败信号不是“程序坏了”，而是 KL 的支持条件不满足。平滑让数值有限，却引入超参数并改变 `p,q`；真实有限样本中的零计数可能是采样不足，也可能代表结构性不可能事件。必须报告平滑规则并做敏感性分析。

不能推出：散度下降不证明域等价、传感器可互换、模型准确、校准良好或存在因果关系。若这是两个医院，还必须分层报告标签/缺失率/设备与下游性能；本课没有医学结论。

参考：[Deep Learning Book Ch.3](https://www.deeplearningbook.org/contents/prob.html)回看 KL 的方向性与零概率行为，8 分钟；看完能把“数学发散”和“代码异常”区分开。

## 常见报错与处理

### 1. `cmake: command not found`

先记录错误和 `PATH`，再检查是否已有 CLion bundled CMake；按[环境检查](#环境检查计入核心-015-分钟)设置 `DAY019_CMAKE`。不要把某台机器的绝对路径永久写入 `CMakeLists.txt`。参考 [CMake Getting Started](https://cmake.org/cmake/help/latest/guide/tutorial/Getting%20Started%20with%20CMake.html)只看 prerequisites，3 分钟。

### 2. `In-source builds are disabled`

你把 `-B` 指向了源码目录。改用 `/tmp/day019-build`。若在临时副本产生 cache，可删除整个临时副本；不要对仓库根目录做递归删除。参考 [`README` 预期失败](../materials/day019/README.md#预期失败禁止源码内构建)，3 分钟。

### 3. 公共头文件找不到

检查消费者是否链接 `divergence` target，库的 include 路径是否为 `PUBLIC`，路径是否指向 `include` 而不是具体头文件。参考 [`target_include_directories`](https://cmake.org/cmake/help/latest/command/target_include_directories.html)只看 scope，5 分钟。

### 4. 改代码后输出仍旧

确认运行的是 `/tmp/day019-build/divergence_demo`，重新执行 `cmake --build`，必要时看时间戳。不要手改 build tree 中生成的文件。

### 5. KL 为负数

先验证概率有限、非负、总和为 1，方向与对数底一致。极小负数可能来自浮点舍入，应看容差；明显负值通常是公式/输入错误。不要取绝对值掩盖问题。

### 6. 把 JS 当成下游任务分数

补报 TV 和真实任务的监督/几何指标；若没有标签或任务实验，就只说“在这一定义下分布不同”，不能说模型更好。散度也不证明因果。
