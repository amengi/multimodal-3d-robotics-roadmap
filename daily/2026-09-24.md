## 概念一：对象、引用和指针

先看最小例子：

```cpp
double distance_m{2.0};       // 一个 double 对象，值为 2.0 m
double& alias_m{distance_m};  // alias_m 是 distance_m 的别名
double* pointer{&distance_m}; // pointer 是保存地址的对象

alias_m += 0.5;               // 原对象变成 2.5
*pointer += 0.5;              // 解引用后修改原对象，变成 3.0
```

关系图：

```text
alias_m ───────────────┐
                       v
                  [ distance_m ] = 2.0 m
                       ^
pointer stores address ┘
```

- 对象有存储和生命周期；值存在对象里。
- 引用绑定后是别名，不能改绑到另一个对象；普通 `T&` 应绑定有效对象。
- 指针本身是对象，保存地址；可以改指向，也可以是 `nullptr`。
- 在声明 `double& alias` 中，`&` 表示引用类型；在表达式 `&distance_m` 中，`&` 是取地址运算。
- 在声明 `double* pointer` 中，`*` 表示指针类型；在表达式 `*pointer` 中，`*` 是解引用运算。

“引用像别名、指针像写着地址的便签”只是入门直觉。真正的正确性条件是：访问时被指对象必须仍存活，指针非空且在合法范围内。

## 概念二：四种传参方式怎么选

| 形式 | 是否复制参数对象 | 是否能修改调用者对象 | 能否表达“没有对象” | 今日用途 |
|---|---|---|---|---|
| `T value` | 是（可能被优化/移动） | 否，修改副本 | 否 | 需要自己的值；小标量常直接按值 |
| `T& ref` | 否 | 是 | 否 | 明确的 in-out 参数 |
| `const T& ref` | 否 | 否 | 否 | 只读访问较大对象 |
| `const T* ptr` | 只复制地址 | 不能通过它修改 `T` | 是，`nullptr` | 可选的、非拥有观察者或连续数据入口 |

今天程序故意定义一个会计数的类型：

```cpp
struct CopyCounted {
    double value;
    static int copies;
    CopyCounted(const CopyCounted& other) : value{other.value} { ++copies; }
};
```

把四元素 `vector` 按值传入，会复制容器内四个元素；按 `const&` 不复制元素：

```text
copy_demo:by_value_copies=4,by_const_ref_copies=0,
          sum_value=4.400000,sum_ref=4.400000
```

这只证明本例的可观察复制行为，不证明所有引用调用都更快。`double`、枚举和很小的值类型通常按值清楚又便宜；优化器、移动语义、缓存和调用约定都会影响真实性能。性能结论需要基准，而不是只数 `&`。

## 概念三：生命周期、作用域与悬空

### 三个词不要混写

- **作用域（scope）**：名字在源代码哪里可见。
- **生命周期（lifetime）**：对象从开始存在到被销毁的时间区间。
- **存储期（storage duration）**：底层存储保留多久；今天重点是局部自动对象和 `vector` 管理的动态存储。

引用或指针的名字仍在作用域内，不代表它指向的对象仍活着。若目标已死亡或地址已失效，引用/指针就悬空；使用它属于未定义行为（undefined behavior, UB）。UB 可能崩溃、打印旧值、似乎正常或在换编译选项后改变，因此“跑一次没崩”不是证据。

### 四种风险

1. **返回局部对象地址/引用**

   ```cpp
   const double* bad() {
       double local{1.0};
       return &local;  // local 在函数返回时死亡
   }
   ```

   不要运行或解引用这个结果；正确做法通常是按值返回。

2. **`vector` 重分配使元素地址失效**

   ```cpp
   const double* observed = &values[0];
   values.push_back(2.0); // 若发生重分配，observed 可能失效
   ```

   修改容器后按规则判断；若可能重分配，就重新取得指针/迭代器。`reserve` 只是容量管理，不是永久安全证明。

3. **空指针**：`nullptr` 没有对象可解引用。本程序先拒绝，再读数据。

4. **越界**：`data + size` 指向尾后位置，可用于比较但不能解引用。本程序用 `index >= size` 拒绝非法索引。

### 所有权

`const double*` 在今天程序中是**非拥有观察者**：调用者拥有 `vector`，观察者只在调用期间读取，不 `delete`。裸指针不自动说明所有权；接口文档必须明确。Day 017 才学习用 RAII/智能指针表达资源所有权。

## 概念四：从自信息到熵

Day 015 的自信息针对一个已观察结果：

```text
h₂(x) = -log₂ P(X=x)   bit
```

离散随机变量的 Shannon 熵是观察前的平均自信息：

```text
H₂(X) = E[h₂(X)]
      = -Σ_x P(X=x) log₂ P(X=x)   bit
```

符号和单位：

- `X`：离散随机变量；今天 `X∈{0,1}`。
- `x`：一个可能结果。
- `P(X=x)`：无量纲概率，所有结果概率和为 1。
- 下标 `2`：对数底数 2，所以单位是 bit；自然对数则是 nat。
- 约定 `0 log 0 = 0`，它来自极限 `lim_{q→0+} q log q = 0`；不是在程序里直接计算 `log(0)`。

熵是分布的摘要，不是样本值本身的属性，也不是任务性能、因果性、校准或风险证明。

## 概念五：Bernoulli 熵手算与最大值

若 `X∈{0,1}`，`P(X=1)=p`、`P(X=0)=1-p`，则：

```text
H₂(p) = -p log₂p - (1-p)log₂(1-p),   0≤p≤1
```

五个关键点：

| `p` | 手算 | `H₂(p)` | 含义 |
|---:|---|---:|---|
| `0` | 结果总为 0 | `0 bit` | 完全确定 |
| `0.25` | `-0.25(-2)-0.75 log₂0.75` | `0.811278 bit` | 偏向 0，但仍不确定 |
| `0.5` | `-2×0.5×(-1)` | `1 bit` | 两结果等概率，二元不确定性最大 |
| `0.75` | 与 `p=0.25` 交换标签 | `0.811278 bit` | 熵对称 |
| `1` | 结果总为 1 | `0 bit` | 完全确定 |

为什么 `p=0.5` 最大？核心路线看两条证据即可：

1. 交换 0/1 不改变不确定性，所以曲线关于 `0.5` 对称。
2. 越接近某个确定结果，猜中就越容易；在 `0.5` 时两结果最难预先确定。

进阶可求导：

```text
H₂'(p)  = log₂((1-p)/p)
H₂''(p) = -1 / [ln(2) p(1-p)] < 0,  0<p<1
```

令一阶导为 0 得 `p=0.5`；二阶导为负说明是唯一内部最大值。

### 常见错误与处理

| 现象 | 原因 | 修正 |
|---|---|---|
| `use of undeclared identifier` | 引用/指针名字超出作用域 | 在合法作用域使用，不扩大对象外的访问 |
| `nullptr` 解引用崩溃 | 地址表示“无对象” | 解引用前验证；如果不需要可空语义，改用引用 |
| `vector` 修改后旧指针偶尔正常 | 重分配后悬空，属于 UB | 修改后重新取得地址；查具体操作的失效规则 |
| `index outside vector` | `index>=size` | 修正索引；不要把尾后指针解引用 |
| `nan` 熵 | 直接算 `0*log2(0)` | 对 `p=0/1` 显式返回 0，解释极限约定 |
| 熵峰值不是 1 | 对数底数或概率和错误 | bit 用 `log2`；检查 `p` 与 `1-p` |
| 把 `0.811 bit` 当准确率 | 指标回答的问题不同 | 同时报任务性能/误差；今天只解释分布不确定性 |

## 跨线小项目：输入、步骤、检查点、输出与验收

### 问题

传感器给出 `ranges_m=[0.8,1.0,1.2,1.4]`。定义事件 `X=1{range<1.1 m}`，用 C++ 非拥有指针读取数据，并同时报告平均距离与事件熵。

### 输入与假设

- 输入 shape `(4,)`，`double`，单位 m，`sensor` 坐标系。
- 指针只在 `vector` 不被销毁、移动或可能重分配的区间使用。
- 阈值 `1.1 m` 是教学规则，不是安全标准或传感器规格。
- 四个观测暂按等权经验样本；若样本相关或选择偏差严重，经验概率解释受限。

### 步骤与就地参考

1. 用 `ranges_m.data()` 和 `size()` 求均值。参考 [LearnCpp：Pointers](https://www.learncpp.com/cpp-tutorial/introduction-to-pointers/)的地址/解引用，5 分钟；能指出谁拥有数组。

- 检查点 A：均值带 `m`，概率无量纲，熵带 `bit`。

一个机器人函数返回 `const Detection*` 指向 `std::vector<Detection>` 的某个元素；调用者保存该指针，然后同一 `vector` 又 `push_back` 多个检测。请给出：所有者、观察者、可能的失效事件、安全改法至少两种，以及即便指针安全也仍需验证的任务指标。

就地参考：[C++ Core Guidelines F.43](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-dangle)和[vector reserve/失效](https://en.cppreference.com/cpp/container/vector/reserve)，共 10 分钟；先独立画时间线。

<details>
<summary>折叠答案（全部独立完成后再展开）</summary>

1. `ref` 是 `x` 的别名；`ptr` 是一个保存 `x` 地址的指针对象。两者访问同一目标，但指针可改指向或为空。
2. 按引用传参不构造新的 `vector` 参数对象，因此不复制四个元素；`const` 禁止函数通过该引用修改容器/元素，但不保证生命周期、线程安全或数值合法。
3. 还需保证目标对象仍存活、地址未因容器重分配等操作失效、目标类型/对齐正确，并且若做数组访问，索引在范围内。
4. 悬空解引用属于 UB，语言不规定结果；崩溃、旧值和表面正常都可能发生，一次运行无法建立可复现规律。
5. `H₂(X)=-Σ_x P(X=x)log₂P(X=x)` bit；Bernoulli 为 `-p log₂p-(1-p)log₂(1-p)`，`0≤p≤1`，概率无量纲，约定 `0log0=0`。
6. `-0.25log₂0.25-0.75log₂0.75=0.5+0.311278=0.811278 bit`。把 0/1 标签互换只会把 `p` 与 `1-p` 交换，和不变。
7. 低熵只表示模型输出分布集中；模型可能自信地错、未校准或遇到分布偏移。至少还要任务性能、校准、鲁棒性/分组结果和失败案例。
8. 均值保留平均物理距离但丢失分布形状；二值熵保留阈值事件的不确定性但丢失原始距离大小和次序。m 与 bit 单位和问题不同，不能比较 `1.1` 与 `1` 的大小来下结论。

**动手任务**：构造含 `std::numeric_limits<double>::quiet_NaN()` 的数组，调用函数并捕获 `std::invalid_argument`；断言确实拒绝。完成后内测数量可以自增，但默认输出应保持，黑盒测试仍通过。

**迁移题**：`vector` 拥有元素，裸指针只是观察者；`push_back` 可能触发重分配，使旧元素地址失效。可改为保存稳定 ID/索引并在使用时重新查找，或在结构上确保容器不再变更后才取指针；也可选择具有合适稳定性/所有权语义的数据结构，但仍要核对其失效规则。指针安全不证明检测正确，还需精度/召回、定位误差、校准、延迟和失败案例等任务证据。
