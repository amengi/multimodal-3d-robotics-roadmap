## 🧭 概念一：广播只看 shape，不理解物理意义

**就地参考**：[NumPy Broadcasting](https://numpy.org/doc/stable/user/basics.broadcasting.html)，只看 General broadcasting rules 与 `(4,3)+(3,)` 例，10 分钟；看完能闭卷写下两条兼容规则。

NumPy 从最右轴向左比较。两个轴兼容，当且仅当：

1. 长度相等；或
2. 其中一个长度为 1。

缺少的左侧轴按 1 处理。结果在每一轴取较大长度。设点云 `P.shape=(N,3)`，平移 `t.shape=(3,)`：

```text
P: N × 3
t:     3
结果: N × 3
```

右端 `3=3`，而 `t` 缺失的左轴视为 1，可扩展为 `N`，所以 `P+t` 合法。广播的“复制”是帮助理解的说法，通常不会真的创建 N 份 `t`；但表达式产生的新结果仍需内存。

两个失败例：

- `(N,3)+(N,)`：最右轴比较 `3` 与 `N`，若 `N≠3` 就非法。若碰巧 `N=3`，代码虽能运行却可能把样本索引误当坐标轴，属于**语义错误**。
- `(N,3)+(3,1)`：从右比较 `3` 与 `1` 可扩展；再比 `N` 与 `3`，通常不等，非法。

不要用“没有报错”代替 shape/单位检查。广播只知道数字，不知道 `(3,)` 是米制平移、RGB 增益还是三个类别权重。

## 🔄 概念二：为什么行点云必须乘 `R.T`

**就地参考**：[Modern Robotics 3.2.1 Rotation Matrices](https://modernrobotics.northwestern.edu/nu-gm-book-resource/3-2-1-rotation-matrices-part-1-of-2/)，只看旋转矩阵表示、逆等于转置和坐标系说明，10 分钟；[NumPy `matmul`](https://numpy.org/doc/stable/reference/generated/numpy.matmul.html) 只看 2-D 乘法签名，5 分钟；看完能把列式逐项转成行式。

本课固定以下约定，换约定必须重推，不能只改变量名：

- `p_s:(3,)`：源坐标系 `{s}` 中的一个点，单位米；数学推导把它看成 `3×1` 列向量。
- `R_ts:(3,3)`：主动、右手旋转，把源坐标的向量表示变到目标坐标 `{t}`。
- `t_ts:(3,)`：源原点在目标坐标中的位置，单位米。
- 单点公式：

  \[
  p_t = R_{ts}p_s+t_{ts}.
  \]

NumPy 点云常把每个点放一行：`P_s:(N,3)`。第 i 行满足

\[
(p_t^{(i)})^T=(p_s^{(i)})^T R_{ts}^T+t_{ts}^T.
\]

把 N 行叠起来：

\[
\boxed{P_t=P_sR_{ts}^T+t_{ts}},
\]

shape 是

```text
(N,3) @ (3,3).T -> (N,3)
(N,3) + (3,)    -> (N,3)
```

这里 `R.T` 来自列向量公式整体转置，不是为了“让 shape 碰巧能乘”。由于 `R` 恰好是方阵，漏掉 `.T` 也不会报 shape 错，却会执行相反方向的旋转，这是最危险的静默错误。

合法三维旋转必须满足

\[
R^TR=I,\qquad \det(R)=+1.
\]

`det=-1` 的正交矩阵含镜像，不是纯旋转；`R^TR≠I` 会改变长度或夹角。

## ✍️ 概念三：完整手算，不把正确性交给计时器

**就地参考**：[NumPy `matmul`](https://numpy.org/doc/stable/reference/generated/numpy.matmul.html)，只看矩阵乘积例，5 分钟；看完能逐行复核下列结果。

取绕 `+z` 轴主动旋转 `90°`：

\[
R=\begin{bmatrix}0&-1&0\\1&0&0\\0&0&1\end{bmatrix},\quad
t=\begin{bmatrix}10\\1\\-1\end{bmatrix}\ \mathrm m.
\]

三个源点（每行一个，单位米）：

\[
P_s=\begin{bmatrix}1&0&0\\0&2&0\\-1&0&1\end{bmatrix}.
\]

逐点列向量计算：

- `[1,0,0] → [0,1,0] + [10,1,-1] = [10,2,-1] m`
- `[0,2,0] → [-2,0,0] + [10,1,-1] = [8,1,-1] m`
- `[-1,0,1] → [0,-1,1] + [10,1,-1] = [10,0,0] m`

所以

\[
P_t=\begin{bmatrix}10&2&-1\\8&1&-1\\10&0&0\end{bmatrix}\ \mathrm m.
\]

程序先断言这份手算，再比较循环与向量化。若先看“向量化快了多少”而未证明数值等价，可能只是在更快地产生错误结果。

## ⚙️ 概念四：向量化改变执行方式，不改变数学任务

**就地参考**：[NumPy Broadcasting](https://numpy.org/doc/stable/user/basics.broadcasting.html)，只看开头“循环在 C 中执行”与末尾内存警告，6 分钟；[Python `timeit`](https://docs.python.org/3/library/timeit.html) 只看重复计时，5 分钟；看完能设计先正确性、后性能的公平对照。

逐点基线：

```python
result = np.empty_like(points)
for i, point in enumerate(points):
    result[i] = rotation @ point + translation
```

向量化版本：

```python
result = points @ rotation.T + translation
```

公平比较至少固定：输入数组、dtype、变换、点数 N、重复次数、软件版本和硬件；先 warm-up，再报告多次中位数。正确性指标是

\[
e_{\max}=\max_{i,j}|P^{loop}_{ij}-P^{vec}_{ij}|,
\]

单位为米。今天要求 `e_max ≤ 1e-12 m`。浮点运算顺序改变时，极小差异正常；不要用 `==` 比较一般浮点结果。

加速比

\[
s=\frac{T_{loop}}{T_{vec}}
\]

无量纲，`s>1` 表示此次向量化更快。它不是普遍常数：N、BLAS、CPU、线程、温度和系统负载都会改变它。某些广播会生成巨大 `(K,N,D)` 中间数组；此时分块循环可能更节省内存，也更清晰。

## 🧩 概念五：同一矩阵语法连接两模态，但不自动产生语义

**就地参考**：[MIT 18.06 Lecture Videos](https://ocw.mit.edu/courses/18-06-linear-algebra-spring-2010/resources/lecture-videos/) 中 Lecture 3，只看矩阵乘法的列组合/行组合观点 8 分钟；[CMU 11-777 Schedule](https://cmu-multicomp-lab.github.io/mmml-course/fall2022/schedule/) 的 Lecture 1，只看 modality/taxonomy 8 分钟；看完能区分“不同宽度特征”与“来自不同采集过程的模态”。

设 A、B 是同一批 B 个对象的两种模态：

\[
A\in\mathbb{R}^{B\times d_a},\quad
B_m\in\mathbb{R}^{B\times d_b}.
\]

这里用 `B_m` 避免把模态 B 和 batch size `B` 混淆。每行由样本 ID 和时间窗配对。两个投影矩阵

\[
W_a\in\mathbb{R}^{d_a\times d},\qquad
W_b\in\mathbb{R}^{d_b\times d}
\]

给出共享宽度：

\[
Z_a=AW_a\in\mathbb{R}^{B\times d},\qquad
Z_b=B_mW_b\in\mathbb{R}^{B\times d}.
\]

`d_a` 与 `d_b` 可以不同，但输出最后一轴都必须是 `d` 才能比较。今天 `W` 是手工构造的教学矩阵，不训练模型。

余弦相似度：

\[
\operatorname{cos}(z_i,z_j)=\frac{z_i^Tz_j}{\|z_i\|_2\|z_j\|_2}.
\]

它无量纲，零向量时未定义。把每行归一化后，所有 A–B 配对的相似度矩阵是

\[
S=\hat Z_a\hat Z_b^T\in\mathbb{R}^{B\times B}.
\]

最小算例取 `Z_a=Z_b=I_2`，则正确配对 `S=I_2`；若交换 `Z_b` 两行，则

\[
S_{swap}=\begin{bmatrix}0&1\\1&0\end{bmatrix}.
\]

高值从主对角线移走，暴露行配对错误。它只说明这个构造的共享几何依赖配对，不是互信息数值，也不证明 A 与 B 因果相关。普通几何对照——矩阵投影、余弦、正确/交换配对——已经回答今天的问题。

## 🚨 常见错误：信号、根因与最小修复

| 信号 | 可能根因 | 最小修复/回归测试 |
|---|---|---|
| `operands could not be broadcast together` | 把 `(3,)` 写成 `(N,)` 或 `(3,1)` | 从右向左写 shape；测试 `zeros((4,3))+array([1,2,3])` |
| 结果 shape 对但旋转方向反了 | 行数组仍写 `P @ R`，方阵掩盖了错误 | 回到列式整体转置；用 `[1,0,0]` 绕 `+z` 90° 应到 `[0,1,0]` |
| `R` 改变了点的长度 | 不是正交矩阵，或混入缩放 | 断言 `R.T@R≈I` 和 `det(R)≈+1` |
| 平移后每列含义混乱 | 单位或坐标系未定义 | 在变量旁写 `{source}->{target}` 与 `m`；拒绝米/毫米混用 |
| `max_error` 很大 | 循环和向量化不是同一公式/同一 dtype | 固定同一输入，打印首个不一致点，不先计时 |
| speedup 每次不同 | 只测一次，N 太小，系统负载/BLAS 不同 | warm-up，多次重复报中位数；结论限定本机配置 |
| 向量化内存暴涨 | 广播生成巨大中间数组 | 估算 `元素数×dtype字节`，沿 N 分块 |
| `matmul` 内维错误 | `W` 写成 `(d,d_a)` 而不是 `(d_a,d)` | 在 `@` 左右标注 `(B,d_a)@(d_a,d)` |
| 余弦得到 `nan` | 某个 embedding 为零向量 | 投影后检查行范数；拒绝零向量而非静默加 epsilon |
| 相似度主对角线很低 | A/B 行号不是同一对象/时间窗 | 用样本 ID 合并，测试交换行故障；不要靠排序猜配对 |
| “两列就是两模态” | 没有不同采集过程与配对定义 | 写采集对象、设备/来源、时间窗、配对键，再使用多模态称谓 |
| 测试通过但不会解释 | 复制参考实现，未做闭卷手算 | 关闭代码重写 3 点例和两个 shape 推导 |

## 🔒 今日必须保留的边界

- 广播按 shape 工作，不懂轴语义、单位或坐标系；能运行不代表物理意义正确。
