## 🧭 概念一：Git 记录的是快照之间的可追踪变化

**就地参考**：[Pro Git：Recording Changes](https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository)，只看 tracked/untracked、staged、`status`、`diff`、`add`、`commit`，12 分钟；看完能对任意文件指出当前状态。

最小模型不是“编辑后直接提交”，而是四个位置：

```text
工作区 ── git add ──> 暂存区 ── git commit ──> 新提交
  │                     │                       │
git diff          git diff --cached      git show / git log
                                                  ↑
                                                HEAD
```

- **工作区**：你现在看到和编辑的文件。
- **暂存区（index）**：下一次 commit 准备包含的快照。
- **commit**：包含内容、父提交、作者/时间与说明的本地历史节点。
- **`HEAD`**：通常指向当前分支，当前分支再指向一个 commit。
- **branch**：一个会随着新提交向前移动的轻量指针，不是完整目录副本。

假设 `train.py` 已被跟踪：

```bash
git status --short
git diff -- train.py
git add train.py
git diff --cached -- train.py
git commit -m "experiment: add validation loss logging"
git log --oneline --decorate -4
```

重要细节：`git add train.py` 暂存的是执行命令那一刻的内容。若随后又编辑 `train.py`，同一个文件可以同时存在 staged 和 unstaged 两份差异；此时必须分别看 `git diff --cached` 和 `git diff`。

语义清晰的 commit 应回答“为什么形成一个独立变更”，例如：

- `chore: add reproducible baseline config`
- `test: reject labels with shape (B,)`
- `experiment: log validation BCE each epoch`
- `docs: record seed and library versions`

`commit` 是本地记录，不自动等于远程备份，也不自动包含未跟踪的数据、虚拟环境、随机种子、运行命令或硬件信息。

## 🌿 概念二：分支合并的是历史，冲突要求人决定语义

**就地参考**：[Pro Git：Basic Branching and Merging](https://git-scm.com/book/en/v2/Git-Branching-Basic-Branching-and-Merging.html)，只看分支切换、三方合并与冲突段，10 分钟；看完能指出 current、incoming 和共同祖先。

若 `main` 与 `experiment-lr` 都从同一祖先出发，并把 `learning_rate=0.10` 改成不同值，Git 无法替你判断哪个实验意图正确，会暂停合并并写入：

```text
<<<<<<< HEAD
learning_rate=0.20
=======
learning_rate=0.05
>>>>>>> experiment-lr
```

- `HEAD` 一侧是当前所在分支的内容。
- 分隔线下方是待合入分支的内容。
- 解决冲突不是机械删除三行标记；必须决定最终语义，例如保留 `0.20`、`0.05`，或基于理由改成 `0.10`。
- 编辑完成后先测试，再 `git add`。在冲突期间，`git add` 的含义是“我已决定此文件的合并结果”。
- 最后 `git commit` 才结束合并并产生双亲提交。

## 🌙 概念三：训练集负责更新，验证集负责观察未参与更新的数据

**就地参考**：[scikit-learn `make_moons`](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.make_moons.html) 看返回 shape、`noise/random_state`，5 分钟；[`train_test_split`](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.train_test_split.html) 看 `test_size/random_state/stratify`，8 分钟。

今天的数据是两个相互交错的半圆：

```python
features, labels = make_moons(
    n_samples=400,
    noise=0.20,
    random_state=20260910,
)
```

- `features.shape == (400,2)`；两列是二维合成坐标，不是两种模态。
- `labels.shape == (400,)`，进入损失函数前改成 `(400,1)`。
- `noise` 是加入坐标的高斯噪声标准差；这里只用于教学难度，不代表传感器标定误差。
- 固定 `random_state` 让相同版本和流程更容易复现。

先分层切分，再只在训练集上拟合标准化：

```python
train_idx, validation_idx = train_test_split(
    indices,
    test_size=0.25,
    random_state=seed,
    stratify=labels,
)

mean = train_features.mean(axis=0)
std = train_features.std(axis=0)
train_features = (train_features - mean) / std
validation_features = (validation_features - mean) / std
```

不能先用全部 400 个样本求 `mean/std` 再切分。即使没有使用标签，验证集的分布信息也提前进入预处理，这属于数据泄漏。今天验证集用于学习监控；如果反复根据它选学习率和 epoch，它已经参与模型选择，不能继续把它称为一次性的最终测试证据。

## 🔁 概念四：训练循环是有顺序的状态更新

**就地参考**：[PyTorch：Optimizing Model Parameters](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)，只看 loss function、optimizer、full implementation，12 分钟；看完能不看答案写出训练与验证两个循环。

网络输入 `(B,2)`，经过 `2 → 16 → 16 → 1`，输出 logit `(B,1)`。二元交叉熵为

\[
\mathcal{L}=-\frac{1}{B}\sum_{i=1}^{B}
\left[y_i\log\sigma(z_i)+(1-y_i)\log(1-\sigma(z_i))\right].
\]

`BCEWithLogitsLoss` 直接接收 logit `z`，内部以数值更稳定的方式合并 sigmoid 与 BCE；训练时不要先手动 sigmoid 再传入。

```python
for epoch in range(epochs):
    model.train()
    logits = model(train_features)       # forward
    loss = loss_fn(logits, train_labels) # scalar loss
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    optimizer.step()

    model.eval()
    with torch.no_grad():
        validation_logits = model(validation_features)
        validation_loss = loss_fn(validation_logits, validation_labels)
```

顺序与作用：

1. **forward**：用当前参数生成 logit。
2. **loss**：把预测与标签压成标量目标。
3. **`zero_grad`**：清掉上一轮累计梯度；它不更新参数。
4. **`backward`**：计算当前 loss 对参数的梯度；它也不更新参数。
5. **`step`**：优化器读取梯度并更新参数。
6. **validation**：不调用 `backward/step`；`eval()` 切换会受训练模式影响的层，`no_grad()` 避免构建梯度图。

今天网络没有 dropout 或 batch normalization，因此忘记 `eval()` 可能暂时看不出数值差异，但接口习惯仍必须建立。只看训练 loss 下降无法判断泛化；至少同时记录 validation BCE 与 accuracy。

accuracy 为

\[
\mathrm{accuracy}=\frac{\#\{\hat y_i=y_i\}}{N},
\qquad \hat y_i=\mathbf{1}[z_i\ge 0].
\]

accuracy 不反映概率校准，也可能在类别极不平衡时误导。今天数据近似平衡，它只是便于入门的共同指标。

## ⚖️ 实践三：用同一证据比较几何基线与 MLP

最近质心基线先在训练集计算两类中心 `c₀,c₁ ∈ R²`，再选择平方欧氏距离较小的类别：

\[
\hat y(x)=\arg\min_{k\in\{0,1\}}\lVert x-c_k\rVert_2^2.
\]

运行：

```bash
python -m materials.day006.compare_methods
```

参考环境输出：

```text
same held-out validation set; metric: accuracy
validation samples: 100
nearest-centroid accuracy: 0.890
MLP accuracy: 0.970
This one synthetic split is a method check, not a universal ranking.
Method-comparison checks passed.
```

公平对照至少保持：相同训练/验证样本、相同标准化、相同 accuracy 定义、相同报告精度。这里 MLP 在这一次合成切分上更高，不能推出“神经网络总比几何方法好”；数据结构、噪声、样本量、超参数和随机种子都可能改变结果。

常见问题：

| 现象 | 可能根因 | 处理 |
|---|---|---|
| `target must be new or empty` | 同名 Git 沙盒已有证据 | 指定临时目录 `day006-git-lab-v2`，不要覆盖 |

| 验证指标异常地好 | 全数据标准化、重叠切分或错用训练集评估 | 审计索引交集与预处理拟合范围 |

### 动手任务与迁移题（先做再展开答案）

1. **Git 动手题**：已执行 `git add train.py`，之后又把学习率从 `0.02` 改为 `0.20`。怎样分别看到已暂存的旧改动和未暂存的新改动？最终 commit 会包含哪个值？
2. **训练迁移题**：有两个真实采集中心 A/B。若随机按样本切分，两个集合中都含同一患者的多次检查，会有什么泄漏？应怎样先定义分组再切分？

<details>
<summary>折叠答案与核对要点</summary>

- A：工作区是当前文件；暂存区是下一 commit 候选快照；commit 是历史节点；`HEAD` 通常经当前分支指向当前 commit。`git diff` 看工作区与暂存区，`git diff --cached` 看暂存区与 `HEAD`。`add` 后继续编辑会形成两份差异。复现实验还需数据、环境、随机性、命令和配置。
- B：分支是可移动 commit 指针；三方合并用两个分支尖端和共同祖先。冲突时 `HEAD` 是当前分支侧。流程为 `status/diff → 编辑 → 测试与 diff --check → add → status/diff --cached → commit → log`。
- C：全数据拟合标准化会让验证分布泄漏进训练流程；shape 为 `(B,2)→(B,16)→(B,16)→(B,16)→(B,1)`；训练顺序是 forward、loss、zero_grad、backward、step。logit 0 对应 sigmoid 0.5。`eval()` 切换层行为，`no_grad()` 禁止记录梯度图。
- D：固定相同 split、预处理、输入、指标，并报告相同统计协议。训练降而验证升是过拟合信号之一。硬件、线程、库版本和非确定性算子仍会造成差异。单个合成数据、单个 seed 和已选超参数不能支持普遍排名。
- Git 动手题：`git diff --cached -- train.py` 看已暂存版本，`git diff -- train.py` 看暂存后继续编辑的版本；若不再 `add`，commit 包含第一次暂存的 `0.02`，不包含工作区的 `0.20`。
- 训练迁移题：同一患者出现在两边会让验证结果利用患者特征，形成身份/重复测量泄漏。先以患者 ID 分组，保证一个患者只属于一个集合；若要检验跨中心泛化，还应按中心设计外部验证，而不是随机混合后声称跨中心有效。

</details>
